1. Alur Kerja Rutin Saat Ada Pembaruan (Workflow Cepat)

Setiap kali Anda selesai mengubah kode di komputer lokal dan ingin menerapkannya ke website live, ikuti 2 tahap mudah berikut:

A Di Komputer Lokal (Mac / PC): Commit & Push ke GitHub 
# 1. Pastikan perubahan kode lokal di-commit dan push ke repository
git add .
git commit -m "Update fitur atau perbaikan terbaru"
git push origin main
B Di Server Hostinger: Terapkan Pembaruan (1 Baris Perintah) 
# 1. Login SSH ke Server Hostinger
ssh -p 65002 u141095167@46.202.138.88

# 2. Masuk ke direktori domain & jalankan deploy script
cd ~/domains/capm.andrichadhea.my.id/public_html
bash deploy.sh
💡 Perintah bash deploy.sh secara otomatis menarik kode terbaru dari GitHub, memicu build container Docker (Frontend Next.js port 3000 dan Backend FastAPI port 8000), dan mengatur hak akses folder secara aman.

2. Prosedur Pembaruan Manual (Jika Tanpa Script)

# Masuk ke direktori server
cd ~/domains/capm.andrichadhea.my.id/public_html

# Ambil update terbaru dari GitHub
git fetch origin main && git reset --hard origin/main && git pull origin main

# Jalankan orkestrasi container Docker

# Atur perizinan file

3. Setup Awal / Pemulihan Server (Fresh Installation)

Jika direktori di server masih kosong atau Anda ingin melakukan instalasi ulang dari nol:

1 Kloning & Sinkronisasi Kode dari GitHub 
# Masuk ke direktori domain di server
mkdir -p ~/domains/capm.andrichadhea.my.id/public_html
cd ~/domains/capm.andrichadhea.my.id/public_html

# Inisialisasi git dan clone repo
git init
git remote remove origin 2>/dev/null || true
git remote add origin https://github.com/Kizker/ai-doc-detector.git
git fetch origin main
git reset --hard origin/main
git pull origin main

# Hapus file default bawaan hosting jika ada
rm -f default.php index.php.bak
2 Jalankan Deploy Script & Konfigurasi .htaccess 
# Beri izin eksekusi script dan jalankan
chmod +x deploy.sh deploy-docker.sh
bash deploy.sh
ℹ️ File .htaccess sudah otomatis disediakan di dalam repositori untuk menangani reverse proxy Apache/LiteSpeed menuju container Next.js di port 3000 lengkap dengan dukungan WebSocket.

4. Deployment Menggunakan Docker (Multi-Container Architecture)

Aplikasi ini berjalan dengan 2 container terisolasi yang dihubungkan melalui internal bridge network ai_doc_detector_net:

Container Name Service Engine Port Peran & Tanggung Jawab
ai_doc_frontend Next.js 14 Standalone 3000 Antarmuka Web, upload dokumen, report viewer
ai_doc_backend FastAPI (Python 3.11) 8000 Ekstraksi teks (PDF/DOCX), scoring NLP, metadata forensik
🐳 Opsi A: Jalankan dengan Docker Compose (Direkomendasikan) 
# Bangun image dan jalankan container di background
docker compose up -d --build

# Cek status container
docker compose ps
docker compose logs -f
⚡ Opsi B: Otomasi Pembaruan Docker (1 Baris Perintah) 
# Jalankan script pembaruan otomatis Docker
bash deploy-docker.sh
🚀 Frontend Next.js dikompilasi dengan mode standalone, memangkas ukuran image dari ~1GB menjadi ~90MB untuk performa server yang ringan dan efisien.

5. Konfigurasi Reverse Proxy (.htaccess & Nginx)

Meneruskan seluruh trafik HTTPS domain capm.andrichadhea.my.id ke container Frontend port 3000:

A. Hostinger / Apache / LiteSpeed (via .htaccess di public_html):

<IfModule mod_rewrite.c>
    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

    # Dukungan WebSocket
    RewriteCond %{HTTP:Upgrade} =websocket [NC]
    RewriteRule ^(.*)$ ws://127.0.0.1:3000/$1 [P,L]

    # Reverse proxy ke Frontend Next.js port 3000
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteRule ^(.*)$ http://127.0.0.1:3000/$1 [P,L]
</IfModule>

B. VPS Nginx Native (Jika Menggunakan Server VPS Dedicated):

server {
    server_name capm.andrichadhea.my.id;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
# Pasang SSL Gratis Let's Encrypt (Certbot)
sudo certbot --nginx -d capm.andrichadhea.my.id

6. Troubleshooting & Tips Penting

⚠️
Error 502 Bad Gateway / Connection Refused:
Pastikan container sedang berjalan dengan mengecek docker compose ps. Jika container berhenti atau crash, jalankan docker compose logs -f untuk menganalisis log backend atau frontend.
⚠️
Upload Dokumen Gagal (413 Payload Too Large):
Pastikan web server mengizinkan upload hingga 50MB. Jika menggunakan Nginx, tambahkan direktif client_max_body_size 50M; di dalam blok server { ... }.
🔄
Tampilan belum berubah setelah deploy (Cache Browser / Cloudflare):
Lakukan Hard Refresh di browser dengan menekan kombinasi Ctrl + F5 (Windows) atau Cmd + Shift + R (Mac). Jika menggunakan Cloudflare, buka menu Caching → Configuration → Purge Everything.
📑
Dokumentasi Interaktif API (Swagger UI):
REST API Backend menyediakan dokumentasi endpoint interaktif yang dapat diakses secara internal melalui http://127.0.0.1:8000/docs.
Dokumen ini digenerate secara otomatis untuk dokumentasi operasional AI Document Detector (capm.andrichadhea.my.id).
